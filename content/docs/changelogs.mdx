## 3.1.0

Unreal Engine plugin. Adds RTMP/RTMPS and live audio/video: receive streams from OBS or FFmpeg, serve RTMP viewers, pull from other servers and publish from Unreal. Existing modules are unchanged. See the [RTMP overview](/docs/Unreal/rtmp).

### RTMP server

* New [`RTMP Server`](/docs/Unreal/rtmp-server) (`URTMPServer`) and the `Create RTMPServer` subsystem node.
* Accepts publishers (OBS, FFmpeg, another Unreal) on port 1935 and hands their media to receivers.
* RTMPS through `Set Tls Options`, using the plugin's TLS layer.
* `Set Allowed Stream Keys` restricts which keys may publish. A second publisher on a live key is refused.
* Playback to RTMP clients (VLC, ffplay, OBS *Media Source*), off by default. Viewers use a **view key** that must differ from the stream key, so the publishing key is never handed out. Optional limit of viewers per stream.
* Viewers have a bounded send queue: under congestion P-frames are dropped and the stream resumes at the next keyframe. Viewers stay connected while the publisher reconnects.
* New events: `On Publish Started`, `On Publish Ended`, `On Play Started` and `On Play Ended`.

### Receive

* New [`RTMP Receiver`](/docs/Unreal/rtmp-receiver) (`UIPRtmpReceiver`): H.264/AAC decoded with Electra and played through the Media Framework.
* `Get Video Texture` for materials and UMG, and `Create Audio Component` for spatialized sound.
* Three ways to start: `Start From Server`, `Start Pull` (`rtmp://` and `rtmps://`, with reconnection and exponential backoff) and `Start Url` (`iprtmp://` or `rtmp(s)://`).
* `Low Latency` (about 150 ms) and `Smooth` (about 1000 ms) jitter buffers, configurable in ms. Audio is the master clock.
* `IP Rtmp Media Source` and an `iprtmp://` media player, also usable with Media Player, Media Texture and Media Plate.
* `On Started`, `On Ended`, `On Error`, `On Frame` and `Get Stats` (fps, bitrate, buffer, drops, rebuffers, decoders).

### Publish

* New [`RTMP Publisher`](/docs/Unreal/rtmp-publisher) (`UIPRtmpPublisher`): streams the viewport, a render target or a scene capture to Twitch, YouTube, MediaMTX, nginx-rtmp or another Unreal.
* H.264 encoded on the GPU through AVCodecs (NVENC, then AMF), with no CPU readback. AAC-LC 48 kHz stereo through Media Foundation.
* Audio from the main submix, a chosen submix, or samples pushed with `Push Audio Samples`.
* Bounded send queue that drops P-frames first, and reconnection with exponential backoff (1 to 30 s) that forces a keyframe.
* `On State Changed`, `On Publishing`, `On Reconnecting`, `On Error` and `Get Stats` (fps, sent bitrate, drops, queue, RTT, reconnections).

### Security

* Stream keys and view keys are never logged, never saved and never `UPROPERTY`. URLs are logged as `rtmp://host/app/***`.
* RTMPS certificates are always verified: the RTMP code never disables verification.

### Native C++ API

* `IRtmpPublishSession`, `IRtmpPlaySession` and `FRtmpIngestHub` (in the `InternetProtocol` module, no media dependencies) for custom pipelines.
* Encoders and decoders are pluggable through `FIPMediaEncoders` and `FIPMediaDecoders`.

### Example map

* New `/InternetProtocol/Example/RTMP/RtmpExample` map: receive, play from a server and publish, with a flash and a beep to check audio/video sync. See [Examples](/docs/Unreal/examples#rtmp-example-map).

### Requirements

* The live audio/video modules (`InternetProtocolMedia`, `InternetProtocolExample`) require **UE 5.8 on Win64**. The networking modules, including the RTMP protocol, support 4.27 to 5.8.
* Publishing needs an NVIDIA (NVENC) or AMD (AMF) GPU. AVCodecs is Experimental in UE 5.8.
* Only H.264 and AAC are supported. `play2`, HEVC/AV1 over RTMP and recording to disk are not.

### Other

* `OpenSSL` is now a public dependency of the `InternetProtocol` module, so modules that include its headers get the OpenSSL include paths.
* New automation tests: AMF0, chunks, FLV, handshake, publish/play loopback over TCP and TLS, view keys, playout clock, encoders, FFmpeg push and pull, publisher to receiver loopback and the example map.

## 3.0.2

Unreal Engine plugin. The networking core was rewritten. Blueprint nodes keep the same names and pins, so existing graphs keep working.

### Threading and stability

* A single shared I/O service with a plugin-managed thread pool (1 to 4 threads) replaces the per-object threads. Each connection runs on its own strand.
* Every event and callback now runs on the Game Thread through weak object references. Destroying an object with pending operations no longer crashes.
* The Game Thread never blocks on network work, and every live connection is closed when the module shuts down.
* `Join Threads` and `Stop Threads` are deprecated and do nothing.
* Writes are queued in order with owned buffers. `Write` / `Send` return false when the send queue limit is exceeded (64 MiB for streams, 16 MiB for UDP).
* `Close` is now graceful: it flushes pending data (and sends TLS `close_notify`) with a timeout. `On Close` fires exactly once per connection.

### TLS

* Secure by default: TLS 1.2 minimum, peer verification with the engine root certificates, SNI and host name verification on clients.
* New `FSecurityContextOpts` fields: `CA_Cert`, `bUseSystemRootCertificates` and `bVerifyHostname`.
* Invalid TLS options now fail with a `TLS configuration failed` error instead of running with a broken context. TLS servers require a certificate and a private key.
* `Verify_Mode = None` on a client logs a warning every time it is used.
* SSL objects created with `NewObject` without `Construct` now use the secure defaults.

### HTTP

* New incremental HTTP/1.x parser for client and server, with case-insensitive headers and limits (64 KiB headers, 64 MiB body).
* Client: requests are queued and sent one at a time over a keep-alive connection. Each callback fires exactly once, with the response or an error.
* Server: requests without a route receive `404 Not Found` automatically, malformed requests receive `400` / `413` / `431` / `501` / `505`, and pipelined requests are answered in order.
* `HEAD` responses are handled without a body.

### WebSocket

* New RFC 6455 implementation: fragmented messages are reassembled, text messages and close reasons are validated as UTF-8, and messages are limited to 64 MiB.
* `End` performs the closing handshake and waits up to 5 seconds for the peer. `Close` aborts immediately.
* `On Close` reports `1005` when no code was received, `1006` when the connection is lost without a Close frame, and `1002` / `1007` / `1009` on protocol violations.
* Pings are answered with a pong automatically.

### Servers

* `Open` / `Bind` accept an IP literal, `localhost` or an empty address. Host names and out-of-range ports fail with an `Invalid argument` error.

### C++

* The public headers no longer expose Asio internals. They include `net/fwd.h` instead of `net/asio.h`, and `get_socket()`, `Construct(io_context)`, `Destroy()`, `connect()` and the `on_close` / `on_request` callbacks were removed from the remote classes.
* `FErrorCode`, `FUdpEndpoint` and `FTcpEndpoint` are exported (`INTERNETPROTOCOL_API`) and have default values. `LogAsio` is exported.
* Asio is configured once in `InternetProtocol.Build.cs` (`ASIO_STANDALONE`, `ASIO_NO_EXCEPTIONS`, `ASIO_NO_DEPRECATED`). An unhandled Asio exception is now a fatal error instead of being silently logged.
* The module now depends on the engine `SSL` module.

### Other

* Updated Asio from 1.36.0 to 1.38.2.
* Added the `InternetProtocolTests` editor module (Win64) with automation tests for TCP, UDP, HTTP, WebSocket, TLS and object lifecycle.

## 2.0

* Implemented server-side socket support for UDP, TCP, HTTP, and WebSocket protocols.
* The HTTP connection now automatically closes when the `Connection` header is set to `close`, or remains open when set to `keep-alive`.
* Enhanced error handling for HTTP requests and WebSocket handshake processes.
* Removed the reconnection attempt functionality.
* Deprecated several outdated HTTP methods.
* Fixed an issue where the SSL socket could only connect once.
* Unreal Engine: Resolved a bug causing events to be triggered outside the game thread.
* Improved handshake validation for the WebSocket client.
