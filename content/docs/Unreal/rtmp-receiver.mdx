The RTMP receiver decodes a live H.264/AAC stream and plays it through the Media Framework: you get a **video texture** for materials and UMG, and a **spatialized audio component**. It can receive a stream published to this machine (OBS, FFmpeg, another Unreal) or pull one from any RTMP server. See the [RTMP overview](/docs/Unreal/rtmp) for complete flows.

<Callout type="warn" title="Unreal Engine 5.8 and DirectX 12 only">
  RTMP is supported only on **Unreal Engine 5.8**, **Win64**, with the **DirectX 12** RHI. Set *Project Settings > Platforms > Windows > Default RHI* to DirectX 12. On DirectX 11 or Vulkan the GPU encoder refuses to start, and publishing fails with an error.
</Callout>

<Callout title="Keep a reference">
  Store the receiver in a variable (Blueprint) or a `UPROPERTY` (C++). An object that nothing references is destroyed by the garbage collector, and the stream stops.
</Callout>

## Latency modes

`EIPRtmpLatencyMode` sets the size of the jitter buffer. Audio is the master clock.

| Mode | Default buffer | Use it for |
| --- | --- | --- |
| `Low Latency` | 150 ms | Lowest delay, on a good local network. More rebuffering on bad networks. |
| `Smooth` (default) | 1000 ms | Internet streams: tolerant to network jitter. |

`Latency Ms` overrides the buffer size of the mode (`0` uses the default above, up to 10000 ms).

## Nodes

### Start From Server

-   Receives the stream published to an [`RTMP Server`](/docs/Unreal/rtmp-server) of this plugin, with the given `App` and `Stream Key`.
-   The server must already be open: otherwise it returns false and `On Error` is triggered.
-   You can start the receiver before the publisher connects: `On Started` fires when the stream arrives.

### Start Pull

-   Plays a stream from an RTMP server: MediaMTX, nginx-rtmp, or another Unreal with [playback](/docs/Unreal/rtmp-server#playback) enabled.
-   `Url` is `rtmp://host[:port]/app` or `rtmps://host[:port]/app`. The `Stream Key` (or view key) is passed separately: it is kept in memory only and never logged.
-   Reconnects with exponential backoff if the connection drops. Server refusals (unknown key, TLS errors...) are reported through `On Error` and are not retried.
-   For `rtmps://`, certificates are always verified.

### Start Url

-   Starts from a single URL:
    -   `iprtmp://host:port/app/key`: a stream published to this machine. The port is served by an `RTMP Server` opened on it or, when none exists, by an internal listener.
    -   `rtmp://host[:port]/app/key` or `rtmps://...`: plays the stream from that RTMP server, like `Start Pull`.
-   Prefer `Start Pull` or `Start From Server` when the key is a secret, so it is not part of a URL.

## Structs

### Receiver Stats

`FIPRtmpReceiverStats`, returned by [`Get Stats`](#get-stats).

| Field | Type | Description |
| --- | --- | --- |
| `Streaming` | Boolean | A publisher is currently sending this stream. |
| `Width`, `Height` | Integer | Video size. |
| `Fps` | Float | Video frames handed to the Media Framework per second. |
| `Bitrate Kbps` | Float | Incoming media bitrate (audio + video). |
| `Buffered Ms` | Float | Media buffered ahead of presentation (jitter buffer). Network and encoder delay are not included. |
| `Audio Sample Rate`, `Audio Channels` | Integer | Audio format. |
| `Dropped Video Frames`, `Dropped Audio Frames` | Integer64 | Frames dropped since the start. |
| `Rebuffers` | Integer | Times the buffer ran out and playback paused to refill it. |
| `Discontinuities` | Integer | Timestamp jumps of more than 1 s in the incoming stream (for example when the publisher restarts). |
| `Video Decoder`, `Audio Decoder` | String | Name of the decoders in use. |

### Video Frame Info

`FIPVideoFrameInfo`, sent by [`On Frame`](#on-frame).

| Field | Type | Description |
| --- | --- | --- |
| `Width`, `Height` | Integer | Frame size. |
| `Time` | Float (double) | Presentation time on the player timeline, in seconds. |
| `Fps` | Float | Frames per second measured over the last second. |

## Media Source

The receiver plays through the Media Framework, so streams also work with your own `Media Player`, `Media Texture`, `Media Sound Component` and **Media Plate**. The plugin registers a media player for these URLs:

-   `iprtmp://0.0.0.0:1935/<app>/<stream key>`: a stream published to this machine. The port is served by an `RTMP Server` opened on it or, when none exists, by an internal listener.
-   `rtmp://host[:port]/<app>[/<key>]` or `rtmps://...`: plays the stream from that RTMP server (pull).

`IP Rtmp Media Source` (`UIPRtmpMediaSource`) is the media source for these URLs. Create it at runtime (Construct Object from Class) and open it with the `Open Source` node of a Media Player.

| Property | Default | Description |
| --- | --- | --- |
| `URL` | `iprtmp://0.0.0.0:1935/live/stream` | Stream URL, see above. |
| `Latency Mode` | `Smooth` | See [Latency modes](#latency-modes). |
| `Latency Ms` | `0` | Jitter buffer target in ms (`0` = default of the mode). |

<Callout type="warn" title="Keys in saved assets">
  A key written in a URL ends up in saved assets and in source control. Set the URL at runtime, or use `Set Stream Key`.
</Callout>
