## Security Context Options

Every `Create ... Ssl` node takes a `SecOpts` struct (`FSecurityContextOpts`). One TLS context is built per object when it is created, and shared by all its connections.

<Callout title="Secure by default (3.0.2)">
  -   TLS 1.2 is the minimum version (SSLv2/3, TLS 1.0/1.1 and compression are disabled). TLS 1.3 is used when both sides support it.
  -   Peer certificates are verified against the engine root certificate store, plus any `CA_Cert` you provide.
  -   Clients send SNI and check that the server certificate matches the address passed to `Connect`.
  -   If the options are invalid (bad certificate, key that does not match, a server without a certificate), connections fail with the `TLS configuration failed` error instead of running with a broken context.
</Callout>

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `Private_Key` | String | empty | Private key, PEM text or base64 encoded ASN.1 (see `File_Format`). |
| `Cert` | String | empty | Certificate, PEM text or base64 encoded ASN.1. |
| `Cert_Chain` | String | empty | Certificate chain, PEM only. |
| `RSA_Private_Key` | String | empty | RSA private key, PEM text or base64 encoded ASN.1. |
| `File_Format` | `EFileFormat` | `pem` | Format of `Private_Key`, `Cert` and `RSA_Private_Key`: `pem` or `asn1`. |
| `Verify_Mode` | `EVerifyMode` | `Verify_Peer` | `None`, `Verify_Peer`, `Verify_Fail_If_No_Peer_Cert` or `Verify_Client_Once`. |
| `Host_Name_Verification` | String | empty | Client: overrides the host name used for SNI and certificate verification (empty = the `Connect` address). Server: name checked against client certificates. |
| `CA_Cert` | String | empty | **New in 3.0.2.** Extra trusted CA certificate(s), PEM. Use it for private or self-signed CAs. |
| `bUseSystemRootCertificates` | Boolean | `true` | **New in 3.0.2.** Trust the platform/engine root certificate store. |
| `bVerifyHostname` | Boolean | `true` | **New in 3.0.2.** Client only: verify that the server certificate matches the host name. |

-   **Servers** must provide a certificate (`Cert` or `Cert_Chain`) and a private key. On a server, `Verify_Mode = None` only means that no client certificate is requested, which is the usual setup.
-   **Clients**: `Verify_Mode = None` disables certificate verification and logs a warning every time it is used. Use it only for local testing.
-   Objects created in C++ with `NewObject` without calling `Construct` use these secure defaults.
