### End

-   Perform a smooth close of socket following ws protocol (RFC 6455 closing handshake) and stop listening for data on it. 'on_close' event will be triggered.
-   Sends a Close frame with `Code` and `Reason`, then waits up to 5 seconds for the peer's Close frame before closing the TCP connection.

<UFunction
  name="End"
  className="WSClient"
  pure={false}
  inPins={[
    { name: "", pintype: "exec" },
    { name: "Target", pintype: "object" },
    { name: "Code", pintype: "int" },
    { name: "Reason", pintype: "fstring" }
  ]}
  outPins={[
    { name: "", pintype: "exec" }
  ]}
/>

### Close

-   Close the underlying socket immediately, without the closing handshake, and stop listening for data on it. 'on_close' event will be triggered with the given `Code` and `Reason`.
-   Prefer `End` for a clean disconnect; use `Close` to abort.

<UFunction
  name="Close"
  className="WSClient"
  pure={false}
  inPins={[
    { name: "", pintype: "exec" },
    { name: "Target", pintype: "object" },
    { name: "Code", pintype: "int" },
    { name: "Reason", pintype: "fstring" }
  ]}
  outPins={[
    { name: "", pintype: "exec" }
  ]}
/>

### On Unexpected Handshake

-   Event triggered when the server answers the upgrade request with an invalid handshake (wrong status, missing `Upgrade` headers or a bad `Sec-WebSocket-Accept`). The connection is not opened.

<UEvents
  name="On Unexpected Handshake"
  showBindNode={true}
  outPins={[
    { name: "", pintype: "exec" },
    { name: "Handshake", pintype: "struct" }
  ]}
/>

### On Message

-   Event triggered when a complete message is received. Fragmented messages are reassembled before this event fires.
-   Text messages are validated as UTF-8; messages larger than 64 MiB close the connection with code `1009`.

<UEvents
  name="On Message"
  showBindNode={true}
  outPins={[
    { name: "", pintype: "exec" },
    { name: "Buffer", pintype: "bytearray" },
    { name: "Is Binary", pintype: "bool" }
  ]}
/>

### On Ping

-   This event will be triggered when a ping has been received. A pong is sent back automatically, so you do not need to answer it.

<UEvents
  name="On Ping"
  showBindNode={true}
  outPins={[
    { name: "", pintype: "exec" }
  ]}
/>

### On Pong

-   This event will be triggered when a pong has been received.

<UEvents
  name="On Pong"
  showBindNode={true}
  outPins={[
    { name: "", pintype: "exec" }
  ]}
/>

### On Close

-   Event triggered when socket is closed. It fires exactly once per connection.
-   `Code` is the close code received from the peer (`1005` when it sent none), `1006` when the connection was lost without a Close frame, or `1002` / `1007` / `1009` when the plugin closed the connection because of a protocol violation, invalid UTF-8 or a message that was too large.

<UEvents
  name="On Close"
  showBindNode={true}
  outPins={[
    { name: "", pintype: "exec" },
    { name: "Code", pintype: "int" },
    { name: "Reason", pintype: "fstring" }
  ]}
/>
